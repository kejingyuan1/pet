## 二、功能完整性缺口（对标竞品）

### 🔴 P0 — 阻塞核心体验
1. **移动端触屏控制：0 处 touch 代码**
   - 用户明确在手机上访问游戏，但整套操作是 WASD+鼠标+空格（桌面专属）。无虚拟摇杆/触屏按钮 → 手机上**无法移动、无法跳、无法交互**（除非外接键盘）。
   - 这是当前最大的可用性阻塞。若"多人在线大世界"目标包含手机，则必须补触屏输入层。

2. **WS 断线无重连（`world-socket.service.ts:69`）**
   - `ws.onclose` 仅 `connected=false; ws=null`，**无任何重连尝试**。后端重启/网络抖动/页面后台化 → 玩家静默失去位置同步、远端玩家、聊天、全部世界交互，只能手动刷新。

3. **无连接状态指示**
   - 用户无法判断 WS 是否存活；断线后界面毫无变化，极易误以为"游戏卡了"。

### 🟡 P1 — 显著差异
4. **无小地图 / 世界地图** — 22岛大世界（散布±2600），玩家极易迷路，无定位手段。
5. **无昼夜 / 天气系统** — 静态光照，探索节奏单调（竞品核心氛围要素）。
6. **无新手引导 / onboarding** — 仅有帮助面板(按H)，无首次进入的引导流程（走向、第一个目标）。
7. **养成深度浅** — 动物只有"收蛋/收奶"，**无成长/繁殖/喂养循环**。`Category` 实体已定义 `growDays`/`feedDays`/`levelReq` 字段（植物养成模型），但大世界未接线；ranch 仅 collect。
8. **社交仅聊天** — 无好友、无玩家间交易、无公会/同居。

### 🟢 P2 — 竞争力补充
9. 任务/成就系统（现有"学习/答题"是独立教育线，未与大世界循环打通）
10. 音效/音乐（audio-director 尚未接入）
11. 表情/动作/emote、截图分享

## 三、合理性问题（机制是否自洽）

1. **跳跃越障落地穿模**：空中飞越树/岩格后，落地贴的是"地面高度"(`heightAt`)，而非树顶高度 → 玩家会"站进"树/岩模型里（视觉穿模）。需确认是否可接受，或落地时按目标格类型抬高。
2. **障碍实际高度 vs 跳跃高度**：跳跃顶点≈1.44格。若树/岩 3D 模型高于 1.44，则"跳过"水平能过但**视觉重叠穿不过去**。需核对 `makeOre`/树模型的真实高度。
3. **矿脉可走但渲染为实体**：玩家会"踩进"矿晶体模型上采矿。可走+可采逻辑合理，但视觉需处理（如矿模型降低/玩家偏移）。
4. **经济平衡缺失**：建造耗100金、采矿收益未见稀缺/通胀设计；养成循环（动物/鱼塘）与金币循环未形成闭环。
5. **文档与实现不一致**：`WORLD_README.md` 写"玩家(圆柱+球)"，实际已换 `boy.glb`；操作表未含跑/双击跑/帮助面板。

## 四、易用性问题（用户能否顺畅使用）

1. **移动端不可玩**（见 P0-1）— 最严重。
2. **无错误边界 / 连接反馈**（见 P0-2/3）— WS 失败静默。
3. **模式按钮无说明**：建造/养鱼/采矿等 7 个按钮无 tooltip，新用户不知各自干嘛、点了会发生什么。
4. **首次进入无引导**：直接进大世界，无"先走到矿脉按F"之类的目标提示。
5. **帮助入口深**：需按 H 或点 ❓，且游戏内无任何"按H看帮助"的提示，新用户发现不了。
6. **数值反馈**：能量条有，但采矿成功/失败、建造成功等**结果反馈**是否每次清晰即时，需实测确认。

## 七、结论

**强项**：服务端权威物理、七种交互模式、真实多人在线共存、养成与经济骨架已立，近期跑功能/越障修复经 E2E 验证。

**关键短板（按影响排序）**：
1. 🔴 手机无法操作（无触屏）— 若目标含手机则体验归零
2. 🔴 WS 断线即失联（无重连/无指示）
3. 🟡 无小地图/昼夜/引导 → 大世界探索缺乏方向感与节奏
4. 🟡 养成偏浅（动物无成长循环）
5. 🟡 社交仅聊天

建议先补 **P0 三项（触屏+重连+指示）**，它们直接决定"能不能玩、断了会不会废"，是成熟竞品的最低门槛。

## 八、P0 三项实施状态（2026-08-14 续）

均已实现并通过 Playwright + 真实 Chrome 的端到端验证。

| 缺口 | 实现 | 验证 |
|------|------|------|
| 🔴 手机无法操作 | `world3d.component.ts` 新增触屏探测 + 虚拟摇杆（pointer 事件 + setPointerCapture）+ ⤴️跳/🏃跑按钮；摇杆向量并入 `sendInputIfNeeded`/`sendJump`（与键盘同源） | `e2e_p0_test.cjs`：手机视口 hasTouch + `?touch=1` → 摇杆产生移动帧(dx/dz≠0) ✅ / 跳跃按钮 `action:"jump"` ✅ / 奔跑按钮指示器 ✅ / console 0 错误 ✅ |
| 🔴 WS 断线即失联 | `world-socket.service.ts` 新增 `connectionState$` + `scheduleReconnect()` 指数退避(1→2→4→8→10s) + `startHeartbeat()` 每5s STOMP 心跳；`connectWs()` 改为订阅 `connectionState$`，每次 `connected` 重建订阅 + 重新 join（断线重连无需刷新页面） | `e2e_reconnect.cjs`：真实 kill 后端 → 指示翻到「重连中…」✅ → maven 重启 → 自动回到「已连接」✅ + 重连后移动恢复 ✅ |
| 🔴 无连接指示 | `world3d.component.ts` 顶部居中徽标 `.hud-conn`（绿=已连接 / 橙=连接中·重连中 / 红=已断开，脉冲动画）+ `connLabel` 文案 | 同上两项 e2e 均验证初始=已连接、掉线=重连中 |

**遗留待确认**：重连后服务端 `join` 是否会让玩家瞬移回出生点（取决于后端 join 处理）；当前重连逻辑优先保证"功能恢复"，瞬移为次要体验问题，必要时再调后端。
